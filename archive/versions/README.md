# Каталог архивов и выпусков — «Из А в Б»

Решение владельца от 31.10.2026: текущий работающий калькулятор получает продуктовое имя **V1 Release**. Предшествующие поколения сохраняются в трёх архивных разделах. Дальнейшие изменения выполняются в одной песочнице.

**Сейчас здесь только проверенные ссылки на полные Git-снимки и правила миграции, а не перенесённый исходный код.** Не объявлять физическую «зачистку» выполненной до построения dependency graph и тестового подтверждения. История Git остаётся доступной.

Новую ветку sandbox создавать только вместе с переносом Preview-окружения и CI/политик допуска.

## Безопасная очистка (НЕ ВЫПОЛНЕНА)

1. Составить полный dependency graph импорта из `app/v3`, `app/v2`, `app/api`, `lib`, `components`, `data`, `scripts`, `experiments`, `vendor`; учесть динамические импорты, файловые данные, Vercel output tracing и GitHub Actions. Сейчас `app/v3/page.tsx` импортирует множество компонентов из `app/v2/components`; удаление `app/v2` сломает V1 Release.
2. Создать **полный переносимый Git bundle** и, по необходимости, архив дерева каждого поколения с манифестом SHA256. До удаления проверить `git bundle verify` и восстановление в чистой директории; не хранить распакованные node_modules, секреты, .env, кеши, бинарные сборки и SDK без проверки прав.
3. У V1 Release вынести используемые V2-компоненты в нейтральный модуль без изменения поведения. Удалять runtime-версии только после тестов; старый URL можно сохранять отдельно или направлять на архивную страницу по согласованной политике.
4. Переместить действительно неиспользуемые эксперименты и отчёты из активного дерева **после** анализа импортов и CI; обновить ссылки handoff, скрипты и workflow. Не считать название директории `experiments` доказательством, что её содержимое не используется.
5. Испытать чистую копию: offline gate, TypeScript, ESLint, Next production build, real API и mobile/desktop; подтвердить сохранение стоимости, платных дорог, GeoNames, спецтерриторий и старого V2 для восстановления. Сверить tree SHA, сохранить checkpoint.
6. При успешной приёмке по отдельному безопасному плану закончить очистку только в песочнице. Production не изменять автоматически; новый выпуск требует отдельной проверки. Существующие backup/main/Android/PR #14 и историю не удалять/не переписывать.

Наличие архивных веток сохраняет доступность исходников, но **не уменьшает физический размер истории Git**. Для уменьшения размера активной кодовой базы — физический перенос и проверка, для уменьшения общего размера репозитория — отдельный план без force-rewrite действующего репозитория.
