# V3 Release Candidate 1 — приёмка локальной версии

Старт: `dbc701fb9560c7b6b3a4e0299734f365c88df4aa`, рабочее дерево clean; разрешённая линия fix/v3-missing-route-prices-2026-10-15. Результаты I1–I3 и bundles сохраняются. Нет push/Production/main/Android/backup/merge/изменения PR14.

Минимальный продукт: выбрать два проверенных населённых пункта (улица необязательна), получить самый быстрый допустимый маршрут, расстояние/время и стоимость трансфера по тарифам; очистить/поменять A/B и рассчитать заново. Крым/новые территории и двойная тарификация входят в основной сценарий. Города работают через разрешённый локальный GeoNames-пилот независимо от Photon. У платных дорог различаются подтверждённая сумма, явно ориентировочная полная оценка и unknown/null; известная часть не выдаётся за полный итог. Старый V2 остаётся доступен.

Один цикл приёмки, внутренняя последовательность без отдельных согласований:

1. Правила поставки и восстановление истории/сохранности I1–I3.
2. Локальный реальный UI/API: GeoNames, A/B/реверс, региональные запросы, mobile; при browser sandbox blocker не отключать защиту, зафиксировать точную границу и продолжить API.
3. Один ограниченный live расчёт (при необходимости второй контрольный), остальные направления/двойная тарификация/состояния цен на сохранённых provider captures через настоящий handler. Replay не выдавать за live.
4. Минимальные исправления воспроизводимых P0/P1; только нужные проверки и финальные обязательные gates по изменённому коду. Сохранённые исходники/тесты I3 использовать, если runtime не изменился.
5. Итоговый release report: PASS/BLOCKED по границам, P0/P1, послерелизные ограничения, локальная публикационная готовность отдельно от Production release acceptance.

Промежуточные checkpoint/WORK_LOG/NEXT_STEPS/commits/readback/bundle — внутреннее сохранение, не новые согласования. Нет массовых маршрутных/GeoNames/тарифных аудитов, нового поиска операторских документов, обхода Deployment Protection или платных API.
