## Найденная ошибка и исправление

В `lib/v3-calculation/route-leg.ts` проверка платных событий выбранной геометрии выполнялась только при включённой диагностике и более двух точках. Положительная известная цена могла скрыть другую обнаруживаемую платную дорогу. В `special-options.ts` такая проверка вообще не передавалась в основной расчёт. Теперь она обязательна для обоих путей, включая геометрию из двух точек. Флаг диагностики не меняет цену. Проверяется геометрия выбранного кандидата, сведения другого провайдера не заимствуются.

`unpriced-road-coverage.ts` при `complete === false` добавляет неизвестный компонент с причиной `selected_route_payment_trace_incomplete`. Сбой сервиса, пустой/неполный ответ не позволяют выдавать известную часть за всю сумму. В API денежные поля такого результата — `null`; подтверждённая бесплатная геометрия сохраняет 0. Старое отсутствие поля complete в изолированных совместимых вызовах не приравнивается к явному отказу; реальный валидатор возвращает метаданные полноты.

В `app/v3/components/response-validation.ts` закреплён контракт одного маршрута: одна leg, одна option при её наличии, отсутствие free/freeCandidate, совпадение конечных точек, расстояния, времени, дорожных сумм/статуса/периода и коммерческих итогов четырёх классов автомобилей. Противоречивый успешный JSON отклоняется до отображения.
