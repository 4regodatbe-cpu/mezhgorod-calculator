# Договор алгоритма платных дорог — нормативный контракт

Дата среза: 2026-10-12
Ветка реализации: experiment/toll-od-matrix-2026-10-08
Статус: контракт для изолированного V3/Preview; сам документ не включает его в V2 или Production.

## 1. Выбор маршрута

1. Для заданных точек и даты/времени маршрутизатор выбирает один допустимый автомобильный маршрут с минимальным ETA.
2. Пользователь видит только его. Альтернативные маршруты не выводятся.
3. Платность, геометрия и сумма вычисляются для того же самого выбранного объекта маршрута. Нельзя пересчитать цену по альтернативной геометрии.
4. Если fastest route платный, он остаётся выбранным, даже если медленный маршрут бесплатный. Если на полностью проверенной геометрии fastest route нет платных участков, сумма равна 0.
5. При равном ETA применяется стабильный документированный tie-break. До появления такого правила нельзя считать выбор среди равных маршрутов детерминированным; сохранять выбранный route ID и порядок кандидатов в диагностике.

## 2. Базовый профиль и календарь

- Легковой автомобиль; категория I используется только если габариты/оси соответствуют официальным правилам оператора.
- Базовый способ оплаты — стандартная оплата без транспондера. Льготы, подписки, пакетные поездки и скидки исключены.
- Дата/день недели и ожидаемое местное время проезда передаются в тарифный адаптер. Время относится к фактическому событию тарификации (ПВП, рамка, въезд/выезд), а не только к старту маршрута.
- Особые календарные правила (праздник вместо выходного, интервалы тарифа, смена ставки в момент проезда) задаёт действующая версия оператора. Не выводить их только из названия «будни/выходные».

## 3. Общее правило доказательств и результата

- Геометрия маршрута, событие платного проезда, принадлежность объекта оператору и строка цены — отдельные факты с отдельными источниками и временем проверки.
- Полная проверенная геометрия без платных событий => 0 ₽.
- Неизвестная сеть, неполный участок, неопределённый ПВП/рамка, неизвестная дата действия или отсутствующая тарифная ячейка на платном маршруте => вся сумма маршрута unknown. Не показывать 0 и не выдавать частичный subtotal как итог.
- Полный итог на нескольких операторах допустим лишь если каждый платный компонент покрыт и межоператорское суммирование подтверждено условиями операторов. Не суммировать тарифные строки автоматически там, где продукт продаётся как единый OD/зональный/коридорный проезд.
- Яндекс Карты сверяет выбранный fastest route, его геометрию и ориентировочную оценку в указанный момент. Оценка не заменяет официальный тариф/расчёт оператора/чек. Несовпадение — диагностический сигнал, не основание подбирать удобную цену.

## 4. Специальный продукт М-4

- Для одного непрерывного проезда по М-4 строится упорядоченный вектор всех ПВП, пересечённых выбранной геометрией, включая первый, последний и все промежуточные известные пункты.
- Ключ тарифной ячейки — полная цепочка между крайними ПВП и профиль/период. Сумма заранее записана в матрице; runtime не складывает цены отдельных ПВП.
- Цена одинакова в обоих направлениях для одного вектора. Для продукта калькулятора два календарных значения: Пн–Чт и Пт–Вс, но каждое значение должно быть подтверждено текущим тарифным источником и датой действия.
- Повторный вход, пропуск промежуточного ПВП, неизвестная граница или вектор без точной ценовой ячейки => unknown. М-4 нельзя тарифицировать старой OD/смешанной моделью как fallback.
- Специальный тарифный коридор/исключение моделируется отдельной схемой до включения.

## 5. Другие модели

Каждый адаптер принимает один выбранный маршрут и конкретную версию тарифа; модель определяется операторским продуктом.

| Тип продукта | Обязательные маршрутные факты | Ключ расчёта |
|---|---|---|
| Фиксированный участок/рамка | подтверждение проезда и время для тарифной сетки | объект + период/время |
| ПВП-вектор или секции | полный упорядоченный список пунктов/секций | точный вектор + период |
| OD-закрытая система | въезд и выезд, направление и операторский режим | OD-ячейка + профиль |
| Зональная/маршрутная цена | пройденные зоны и правила маршрута | опубликованный продукт/коридор |
| Free-flow | подтверждённые камеры въезда/выезда или секции | полный операторский маршрут |
| Транзит с условиями | все требуемые въезды/выезды, класс/регион ТС, дата и исключения | подходящий транзитный продукт |
| Сопряжённые сети | граница ответственности и правило сложения/единый продукт | документированное правило оператора |

Неподходящий ключ (например, километровая ставка вместо опубликованного OD) запрещён.

## 6. Трассировка и версия тарифа

Для каждого значения хранить: operator/network/product ID, точный URL и тип документа, дату публикации/редакции, дату начала действия, дату проверки, профиль класса/осей, способ оплаты, календарный период/время, направление, точный объект или OD, валюту/сумму, исходную строку/артефакт и статус проверки. Без даты действия цена не считается пригодной для точного live-итога.

## 7. Приоритет и открытые пункты

Этот документ — единый актуальный контракт песочницы и имеет приоритет над старыми заметками, где предполагались альтернативы, неполная геометрия или per-PVP суммирование М-4. История решений сохраняется в DECISIONS.md и журналах.

Открыто на дату:
- tie-break равного ETA требуется формализовать в коде;
- матрица М-4 содержит 0 независимо проверенных ценовых ячеек;
- действующую таблицу Автодора не удалось открыть напрямую (HTTP 403), индексируемый фрагмент конфликтует с сохранённым M-3 тарифным снимком; суммы не перезаписывать;
- 22 сетевые группы не являются доказанной исчерпывающей переписью всех платных объектов РФ; состав дочерних продуктов описан в national-registry.json;
- полный расчёт и текущие цены большинства операторов пока не готовы к пользовательскому итогу.
