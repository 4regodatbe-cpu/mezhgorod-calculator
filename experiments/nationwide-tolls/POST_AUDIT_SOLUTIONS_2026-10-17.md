## Что действительно мешает расчёту

Большая часть оставшихся находок связана с тем, что выбранный след нельзя однозначно сопоставить с готовой тарифной парой конкретной дороги. Это разные задачи привязки по разным продуктам. Нельзя решать их ослаблением всех проверок или одной общей суммой. У каждой дороги остаётся собственная готовая матричная пара; вся поездка тарифицируется по отправлению.

13 записей аудита имеют исходы: 1 исправлена и проверена (A-289 component binding, не полная цена всех маршрутов), 1 не воспроизвелась, 8 заблокированы надёжными данными, 3 отложены. Исторические исправления M4/A289/ZSD identity сохранены в completedFixes очереди; число этих коммитов не равно числу текущих открытых причин. ## Первый конкретный объект решения: ЗСД

Представитель: сохранённый fastest route `dnr-гранитное-saint-petersburg-center`; уже доказаны северный основной ПВП5 (OSM node 933974870) и съезд к набережной Екатерингофки. Старое доказательство: [точная область](../../docs/checkpoints/2026-10-16-1406-zsd-granitnoe-exact-scope.md). Нового live/replay здесь нет.

[Текущий адаптер](../../lib/v3-calculation/zsd-zone1-component.ts) сознательно ограничен зоной 1: любой иной paid way вызывает `zsd_trip_extends_outside_reviewed_zone1`. Значит, расширение списка имён/way IDs не решает недостающий тарифный охват. Нужен отдельно доказанный законченный вектор проезда; готовую сумму такого вектора можно брать из матрицы после подтверждения.

В сохранённых [правилах владельца](source-snapshots/zsd/2026-10-15-zone1/whsd-owner-rules.html) повторно проверены пункты 6.2.2, 6.2.17 и 6.3. Новое существенное ограничение для проектирования: **п.6.2.17 предусматривает связанную оплату Автомобильная улица↔Благодатная улица по первому чеку при соблюдении условий и интервала 60 минут (либо интервала на чеке)**. Поэтому два пересечённых физических шлагбаума нельзя автоматически превращать в две независимые платы. Эта норма не подтверждает сумму для Гранитного→СПб и не позволяет назначить 300/600 ₽ наугад.

Таблица [базовых тарифов владельца](source-snapshots/zsd/2026-10-15-zone1/whsd-owner-tariffs.html) и старые первичные правила уже сохранены. Контрольный запрос 17.10.2026 к whsd.ru/tarifyi-na-proezd и whsd.ru/pravila-ispolzovaniya-zsd вернул 502 через web retrieval; www.nch-spb.com вернул 403. Найденные PDF «Транспондер» не подходят пользовательскому профилю без транспондера. Непервичные отзывы/новости не использованы для назначения цены. Нового независимого доказательства законченной cash/card схемы не получено; причина сохраняет статус blocked_by_missing_reliable_data.

### Следующий шаг и критерий завершения

Найти первичную схему ПВП5→тарифные зоны/съезды для наличных/карты и связать её с уже сохранённой направленной геометрией КАД-юг→Екатерингофка. Допустимо использовать опубликованную оператором схему/публичный тарифный расчёт либо документированное подтверждение проезда, но не транспондерную цену и не предположение по числу ПВП. Не повторять поиск общей таблицы зон: он не отвечает на вопрос о взимании платы.

После доказательства: отдельный законченный вектор в матрице, положительная проверка точного сохранённого пути и проверки исключений (обратное направление, неполная зона, Автомобильная↔Благодатная с условиями чека, безбарьерная ветка). Затем focused/full gate по AGENTS и ограниченный replay; одинаковые области переносить только после проверки инвариантов. Если первичного доказательства нет, сохранить конкретный недостающий факт и перейти к следующей причине, не расширяя бесконечный поиск.
