# Дорожные переходы и существующая тарифная матрица

Реализовано23.10.2026 для распознавания въездов/съездов М4 в выбранном маршруте OSRM или Valhalla. Существующая матрица и цены сохранены. Незаполненная цена не мешает определить направленный вектор.

## Поток данных

Provider response → номера/названия реально пройденных дорог → конкретный переход с координатой и направлением → запрос существующей матрицы. Указатели destinations и старые begin_street_names не считаются проездом по дороге. Номер дороги без места перехода не уникален. Все данные связаны с SHA256 полной выбранной геометрии; инструкции другого маршрута не принимаются.

Код: lib/toll-engine/road-boundaries.ts, lib/route-providers.ts, lib/toll-engine/m4-production.ts, lib/v3-calculation/route-leg-pricing.ts и experiments/nationwide-tolls/engine/m4-route-adapter.mjs. Формат preview: m4PvpPreview.roadBoundaries и tariffVector. Точность route-maneuver означает место перехода в инструкциях маршрутизатора; это не OSM node ID и не подтверждение операторской области взимания.

## Цена и границы проверяются отдельно

- resolved: определены оба перехода между дорогами в одном непрерывном проезде.
- partial: один конец поездки находится непосредственно на целевой дороге либо не хватает данных короткого соединителя.
- unknown: разрыв/невалидные данные, несколько проездов или чужая геометрия.
- not-detected: строгий номер целевой дороги не обнаружен.

При подтверждённых ПВП продолжают использоваться существующие тарифные ключи. При наличии фактического платного кандидата, определённых дорожных переходов и отсутствии подтверждённых ПВП выбирается отдельный дорожный вектор. Lookup использует тот же endpoint quote engine с road=m4-candidate. Нет подходящей строки цены → tolls=null, reason=m4_road_vector_price_unknown; неизвестное не превращается в0. API целого маршрута сохраняет amount=null/pricingStatus=unknown.

Ключи переходов содержат provider, направление и координату. Между разными providers они автоматически не приравниваются. Геометрия манёвров не доказывает тарифную область; варианты545-a/b и короткие области взимания нельзя выбирать по ближайшему ПВП. Чтобы заполнить цену позднее, требуется проверенная направленная строка с точными границами, профилем и действием тарифа, совместимая с существующим endpoint register; не менять priceStatus вручную и не назначать соседний тариф.

## Проверенный сохранённый случай

Гранитное→Казань, выбранный Valhalla маршрут1696588м. Въезд: Северный обход Ростова-на-Дону→М4, координата(lon,lat)=[39.838698, 47.378414]. Съезд: М4→Р260, [40.265878, 48.186303].

- from: `road-transition:dd09b189870270c9800edefc`
- to: `road-transition:9f147230b739802282d36415`
- profiles: monThu / friSun; цены пока неизвестны.

Полная выбранная геометрия сохранена без изменения. Replay использует один исходный provider response и его ранее сохранённую полную trace; новых live-запросов нет. Это один проверенный маршрут, не подтверждение всех направлений новых территорий и не операторское доказательство суммы. Машинный результат: checks/2026-10-23-integration/selected-vector.json.

BRouter не предоставляет используемый набор инструкций: для него остаётся прежний путь проверки ПВП. Самостоятельная локальная дорожная сеть не создавалась.
