# Точные переходы М4 и существующая тарифная матрица

Актуальная реализация23.10.2026 использует графовые данные полного map matching именно выбранного маршрута. Метод применяется после выбора самой быстрой геометрии и не перестраивает её. Новые сетевые запросы не добавлены: используются уже получаемые trace_attributes. Собственная карта страны не создавалась.

## Почему инструкции недостаточны

В сохранённом Гранитное→Казань инструкция начинает манёвр заранее, на Северном обходе Ростова. Это подсказка о коридоре, но не точный въезд на М4. Ранний слой route-maneuver и исторический checks/2026-10-23-integration остаются диагностикой; их координаты нельзя принимать за тарифные границы.

Активное доказательство: precision=matched-road-edge. Сохраняются фактический OSM node и направленная пара OSM way IDs до/после перехода. Идентификатор не зависит от того, какой provider выбрал геометрию. Связь с конкретным маршрутом защищена SHA256 всей геометрии и complete/boothEventCoverage=complete. Безымянная подъездная дорога также может иметь точную графовую идентичность.

Соседние trace chunks сшиваются только по одному однозначному общему фрагменту направленных way+end-node. Индексы выходных shapes не сравниваются между chunks и не используются как индексы исходного маршрута. Неоднозначность внутри М4, разрывы, повторные въезды и неполное покрытие остаются unknown. Неподтверждённые стыки вне целевого участка не заменяют и не стирают уже доказанные границы М4.

Поле coordinate у точного графового перехода сейчас null: текущие ответы не содержат декодированную выходную shape. Узел известен точно, координата не угадывается по инструкции. В API доказательство находится в m4PvpPreview.roadBoundaries, выбранный вектор — в tariffVector. Отсутствие optional M4-поля у другой дороги не означает бесплатность.

Шесть сохранённых случаев с Казанью: Гранитное, Талаковка, Новоазовск, Широкино, Розовка и Гуляйполе. Во всех случаях полный selected trace указывает одну пару:

- Въезд: [OSM node4443232947](https://www.openstreetmap.org/node/4443232947), way447135768→1182567076. Это переход с подъезда к аэропорту Платов на М4.
- Съезд: [OSM node358467208](https://www.openstreetmap.org/node/358467208), way1211606940→28835034, М4→Р260.
- from: `osm-transition:4443232947:447135768>1182567076`
- to: `osm-transition:358467208:1211606940>28835034`

Проверено6 геометрий и12 профильных оценок одного физического вектора; это не шесть независимых развязок и не аудит всех направлений. Новых live-запросов0. Полный provider→13 trace chunks→V3 composer→API отдельно воспроизведён для Гранитного в двух профилях: границы resolved, amount=null, pricingStatus=unknown. Реальные шесть captures выбраны Valhalla; общая схема не требует инструкций BRouter, этот путь покрыт отдельным синтетическим контрактным тестом.

## Заполнение тарифов позже

Подтверждённые ПВП продолжают использовать существующие цены и ключи M4_ACTIVE_ENDPOINT_REGISTER.json. Для точных графовых переходов добавлен M4_GRAPH_ENDPOINT_REGISTER.json; это расширение того же endpoint quote engine, не отдельная система расчёта. Его rows сейчас пусты. pending содержит одну пару для шести случаев, два профиля и неизвестные цену/операторскую область взимания. Pending никогда не участвует в начислении.

Будущая строка rows должна иметь road=m4-candidate, точные from/to, profile, rub, источник и срок действия, scopeBindingStatus=reviewed и runtimeEligible=true. Для неё сохраняются существующие проверки версии тарифа и профиля, а также отметка неподтверждённой цены. Простое переименование pending или добавление приблизительной суммы не доказывает взимание платы.

Когда границы определены, а точной строки цены нет, выбирается стабильный вектор с reason=m4_road_vector_price_unknown. Полная сумма маршрута остаётся неизвестной; отсутствующая цена не0. Ближайший ПВП, варианты545-a/b, отсутствие mapped booths и одно имя М4 не заменяют операторскую область взимания.
