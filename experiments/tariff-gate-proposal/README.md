## Соответствие решениям27–28октября

StageAD правильно отделял возраст наблюдения от действительности цены, но демонстрационный boolean-evaluator не являлся готовым контрактом CI. Здесь stale даёт WARNING независимо от возраста официального документа. Неизвестная юридическая effectiveFrom даёт предупреждение; она не блокирует явно принятую рабочую модель с сохранённым обоснованием применимости. Последняя доступная официальная редакция продолжает применяться до более новой применимой редакции; искусственный validTo не создаётся. Принятый рабочий продукт допускается без требования чека/сертификации каждой полосы. Это не превращает неизвестный физический продукт в известный.

Строгие ошибки: невалидная/будущая дата наблюдения, ошибочная/будущая дата применения, отсутствие проверенного официального источника или денежной ячейки, существенный/неразрешённый конфликт, неизвестный продукт и риск двойного начисления. Новая редакция после даты поездки не разрешается как историческая ставка. Реестр CI оценивается на asOf; runtime исторического выбора редакций не меняется.

## Обязательная доказательная запись

После применения patch strict CLI требует `TARIFF_GATE_EVIDENCE` — путь к reviewed JSON schemaVersion1 с rows: ровно одна запись на каждый id текущего реестра. Без файла/с неполными записями остаётся exit2; stale не превращается в автоматический PASS.

Поля записи: id; source:{officialDocumentReviewed:true,url:https URL,path:сохранённый относительный путь,sha256:реальный SHA256}; fareKnown:true; versionBasis:latest_available_official_document; applicability:{status:verified либо accepted_working_calculation,basis:конкретное обоснование периода}; contradiction:none; productBinding:verified либо accepted_working_calculation; doubleChargeRisk:false. Это проверенные выводы reviewer, не значения по умолчанию. Нельзя заполнять их из предположений. `officialDocumentReviewed` подтверждает содержательную проверку первичного источника человеком/агентом; один URL/хеш сам по себе официальность не доказывает. Файл и его checksum проверяются локально, выход за root/отсутствующий/изменённый документ отклоняется. Никаких сетевых запросов из gate.

StageAG уточняет это экспериментальное поле: `applicability.effectiveFrom` обязательно для `status:"verified"`, валидируется как календарная дата/ISO instant и не может быть позже `report.asOf`; неверная дата блокирует. У `accepted_working_calculation` точная юридическая дата может остаться неизвестной по принятой политике, но основание должно быть заполнено. Это изменение только proposal evaluator `gate.mjs`; `approval.patch` всё ещё подключает этот evaluator, mandatory script не менялся.

Stage AF проверил две `avtodor-other-roads` строки по сохранённым первоисточникам. Приложения приказов №53 (М‑3), №56 (ЦКАД) и №55 (А‑289) сохранены как сканированные official PDFs, визуально проверены; пути, SHA256, категория I, payment basis и effective date 02.03.2026 внесены по каждой дороге в `avtodor-other-roads-evidence-2026-11-07.json`. По М‑1 указан официальный URL приказа №54 и дата из metadata реестра, но сам первичный PDF и исходный HTML/response tariff page отсутствуют. Поэтому обе общие записи намеренно `coverageComplete:false`, а `fareKnown:false`; возраст `observedAt=2026-10-01` является предупреждением и сам по себе не прекращает применимость.

Изолированный assessor дополнен проверкой `coverageComplete`, чтобы частичный комплект четырёхдорожного snapshot не мог пройти по одному или нескольким PDF. Временное применение `approval.patch` с этими записями выдало stale warnings и ожидаемый strict exit2: не доказана М‑1 и отсутствуют reviewed rows для M‑11/M‑12, поскольку схема требует все четыре IDs. Это не активный CI результат и не тарифный PASS. Следующий шаг: получить/сохранить исходный официальный артефакт М‑1 по существующему URL или оригинальную страницу, подготовить записи M‑11/M‑12 из уже сохранённых документов, затем предъявить patch/evidence владельцу.
