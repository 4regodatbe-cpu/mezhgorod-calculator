## Целевая архитектура

1. Route Builder — несколько независимых кандидатов маршрута.
2. Map Matcher / Toll Validator — независимая проверка фактических дорожных рёбер и ПВП.
3. Toll Engine — расчёт платы по реальным ПВП/рамкам/системам entry-exit/free-flow.
4. Free Route Arbiter — бесплатный маршрут считается бесплатным только после независимой проверки.
5. Fallback — проверенная база и коридорная логика используются только как резерв.
6. Regression QA — автоматическая проверка эталонных проблемных направлений после изменений.

### 4.6. Оставшиеся тарифные блокеры после точного обнаружения — В РАБОТЕ

Текущий event engine намеренно возвращает `amount=null`, потому что три тарифных случая ещё не формализованы:

1. Mixed 401–464: для контрольных long-haul маршрутов подтверждены 416 и 460. По правилам Автодора оплата происходит на въездном ПВП, повторное списание на выезде не производится при валидном проезде в пределах 12 часов. Для полного сквозного проезда нужно начислять тариф участка один раз: 360/480 руб.
2. Mixed 633–741: на всех контрольных mainline-маршрутах подтверждён 636 и отклонён 672. По текущей тарифной сетке mainline ПВП 636 имеет 640/770 руб.; ПВП 672 — отдельный 440/500 руб. и участвует в логике частичного маршрута 633↔672 / временного окна 120 минут.
3. ПВП 545: один физический ПВП обслуживает две последовательные тарифные строки 517–544 (160/220) и 545–589 (250/300). Для сквозного long-haul маршрута через обе стороны нужно начислять обе строки один раз, но только при подтверждённом route-context; одиночный 545 без контекста остаётся ambiguous.

Дополнительно: текущая функция определения ПН–ЧТ / ПТ–ВС пока учитывает только день недели. Перед production включением нужно учесть официальные нерабочие праздничные и предпраздничные дни.

## Принцип безопасности изменений

- Не расширять радиусы, чтобы скрыть отсутствие данных.
- Радиус кандидата не является доказательством пересечения.
- Не подставлять цену другой пары городов.
- Не считать `avoid tolls` доказательством бесплатности.
- Не выдавать точную сумму из неполного набора ПВП.
- Не складывать entry/exit ПВП mixed-систем как независимые тарифы.
- Неподтверждённые кандидаты не становятся полной уверенностью автоматически.
- Любая новая схема сначала диагностическая и проходит regression, только потом становится основной.
