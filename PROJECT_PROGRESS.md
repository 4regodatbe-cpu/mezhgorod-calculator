## Целевая архитектура

1. Route Builder — несколько независимых кандидатов маршрута.
2. Map Matcher / Toll Validator — независимая проверка фактических дорожных рёбер.
3. Toll Engine — расчёт платы по реальным ПВП/рамкам/системам entry-exit/free-flow.
4. Free Route Arbiter — бесплатный маршрут считается бесплатным только после независимой проверки.
5. Fallback — проверенная база и коридорная логика используются только как резерв.
6. Regression QA — автоматическая проверка эталонных проблемных направлений после изменений.

## Этап 2. Независимый Toll Validator / map matching — ЗАФИКСИРОВАНО

Сделано:

- `lib/toll-validator.ts` использует Valhalla `trace_attributes` для независимой проверки готовой полилинии.
- Длинный маршрут разбивается примерно на 140-км части, чтобы map matching не падал на длинных трассах.
- Из результата собираются:
  - `edge.toll`
  - `way_id`
  - названия дорог
  - события `toll_booth`
  - OSM node id ПВП, когда он доступен
- Бесплатный маршрут не считается подтверждённо бесплатным, если validator видит платное ребро/ПВП.
- Для unresolved toll быстрый маршрут тоже может проходить map matching; дорогая диагностика не запускается без необходимости на каждом обычном расчёте.

Статус: `готово как техническая основа`, требуется расширение источников и использование событий ПВП в новом Toll Engine.

## Принцип безопасности изменений

- Не расширять радиусы, чтобы скрыть отсутствие данных.
- Не подставлять цену другой пары городов.
- Не считать `avoid tolls` доказательством бесплатности.
- Не считать mixed entry/exit как обычный фиксированный ПВП.
- Любая новая схема сначала работает диагностически и проходит regression, только потом становится основной.
