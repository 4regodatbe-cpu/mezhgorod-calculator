`lib/v3-calculation/special-options.ts` вызывает Valhalla/OSRM для candidate plans, отбрасывает неуспешные или непригодные маршруты и выдаёт `PREFERRED_ROUTE_UNAVAILABLE`, когда подходящих options нет. Публичная ошибка соответствует `lib/calculate-api-error.ts`. Поскольку исходные причины каждого provider rejection не входят в публичный JSON и здесь не сохранена геометрия, **нельзя утверждать**, что оба провайдера недоступны: маршрут мог быть отклонён проверками пригодности/коридора/растяжения. Подтверждена лишь граница отказа: `special_options/routing` раньше `response_pricing`. Общее время около 5–6 с, не 90-секундный тестовый deadline.

Наблюдение владельца о построенном маршруте Донецк → Волноваха без четырёх сумм и о 614,2 км Донецк → Мелитополь этим локальным прогоном **не воспроизведено и не опровергнуто**: код/среда/геометрия Preview могут отличаться. `app/api/v3/calculate/route.ts` вызывает `attachPricing` только после получения route; `lib/route-pricing-integration.ts` возвращает `totalPrice:null`/`requiresSplit:true` при отсутствующем или несогласованном territory split. Это возможный, но не доказанный для указанного маршрута механизм. Подозрительный путь, разбивка обычного/особого пробега и четыре тарифа остаются UNKNOWN; не изменять геополитику, правила, ставки или маршрутизатор по этой попытке.

Чтобы завершить AUDIT-01, нужен первичный JSON именно успешного Preview-ответа (source SHA, from/to coordinates, departureAt, выбранный provider/geometry либо сохранённая trace, split, `pricingByVehicle`, `Server-Timing`) для обоих наблюдений; при новом live-прогоне также нужны безопасные диагностические причины rejection провайдеров. Не повторять те же два запроса в неизменной среде без отличия условий.
