## Задание по устранению блокеров калькулятора Из А в Б


### Для кого и какой результат нужен

Документ предназначен разработчику, специалисту по геоданным и исследователю тарифов, ранее не работавшим с проектом. Нужно обеспечить устойчивый выбор адресов и корректный полный расчёт платных участков самого быстрого допустимого маршрута. Для каждого пакета ниже требуется либо проверенное исправление, либо точный перечень недостающих данных с доказательствами. Переписывать весь алгоритм не требуется.

Дата состояния 24 октября 2026 года. Опубликована V3 из commit da77f96; V2 сохранена как старый алгоритм. Репозиторий содержит последующие записи выпуска: исходная точка этого задания c959bc2. Перед работой сверить текущий удалённый commit и PR, поскольку код мог измениться.


### Как работает расчёт

Пользователь выбирает населённые пункты или адреса A и B. Интерфейс отправляет запрос поиска через POST /r в /api/suggest. Photon возвращает варианты с координатами. Без надёжных координат расчёт не должен начинаться.

Расчёт V3 обращается к маршрутизаторам OSRM и Valhalla согласно ветке алгоритма; для специальных территорий действует географическая политика. Из допустимых маршрутов выбирается самый быстрый. Затем полный trace этого маршрута сопоставляется с дорогами, ПВП и направленными въездами и съездами.

Тарифный движок ищет действующую строку для доказанного участка, категории автомобиля и даты отправления. Известные компоненты суммируются только при доказанной полноте. Далее рассчитывается стоимость поездки по ставкам калькулятора; дорожные сборы не следует смешивать с рублями за километр услуги.


### Главный принцип работы

Неизвестная цена не равна нулю. Известная часть сборов не является полной суммой. Наличие дорожного номера, платного тега или километра ещё не доказывает тарифную пару. Часть блокеров ниже — нехватка надёжных данных или проверок, а не установленная ошибка программы.

## B01 Устойчивый поиск адресов при отказе Photon


### Проблема и влияние

При полном HTTP 503 от Photon новый адрес без положительного кэша не находится. Все семь вариантов URL для Донецка идут в один сервер источника photon.komoot.io: это один источник, а не семь резервов. Пользователь видит временную недоступность; смена запроса или увеличение времени ожидания не создаёт координаты.


### Что уже работает

Есть ограничитель: 2 одновременных запроса на процесс, очередь 64, объединение одинаковых запросов, независимая отмена и положительный кэш на 128 адресов запросов на 5 минут. Общий бюджет времени 20 секунд. Пауза включается после 3 отказов 503/429 за 15 секунд без успешного ответа; успешный ответ сбрасывает паузу. Это проверено. Между серверными экземплярами приложения нет общей очереди или гарантированно общего кэша.


### Задание исполнителю

Прочитать сборщик ответов и /r, установить границу полного отказа unavailable=true. Подготовить допустимый независимый источник автодополнения либо проверенный локальный каталог B02. Сохранить обычный успешный, частично успешный и успешно пустой ответ Photon. Не подставлять резерв только потому, что результатов мало.

Встраивать резерв отдельным отключаемым модулем, в остаток тех же 20 секунд. Учитывать AbortSignal; не выполнять новый длительный внешний поиск после истечения бюджета. При невозможности получить проверенную точку вернуть явную ошибку, а не пустую уверенную выдачу. Положительный кэш помогает повторным запросам, но не решает полный отказ для нового города.


### Как принять результат

На детерминированных отказах 503/429 показать корректную ограниченную выдачу только для допустимых записей. Проверить отмену, очередь, cooldown, частичный и пустой ответ и отключённый модуль; ни один тест не должен превращать отказ в фиктивный адрес. Затем отдельно проверить реальный источник с лимитом запросов. Указать его лицензию, лимиты и границы покрытия.

Выход: небольшой PR с кодом, переключателем, контрактными тестами, воспроизведением исходного отказа и журналом. Если источник недоступен — конкретный статус блокировки, URL/время/ответ, без серии одинаковых повторов.

## B02 Проверенный резерв населённых пунктов


### Текущее состояние

GeoNames России и Украины уже доставлены через CI. Разобраны 237006 записей класса P; диагностическая выборка восьми имён содержит 93 кандидата. Русские имена есть у 92 из 93 городских записей. У 77 из 93 базовых административных записей есть русский вариант названия, но два записаны латиницей. Дополнительное сопоставление 44 ADM3/ADM4 не дало русских вариантов названий; после отбраковки сомнительных подписей остаётся 19 групп одинаковых подписей.

Два населённых пункта Тарасовка в ДНР имеют GeoNames IDs 691877 и 9529726; две Ялты —688531 и 688532. Нельзя склеивать записи или брать первую. Проверка диапазона WGS84 подтверждает корректный формат чисел, но не фактическую точность центра. Полнота регионов не установлена, покрытие Крыма остаётся UNKNOWN.


### Что нужно найти

Для выбранных точных ID получить независимый источник текущего названия, района или иной различающей подписи и географической позиции. Сопоставлять по идентичности, коду территории и источнику, а не по ближайшей точке. Перспективные направления: официальный реестр населённых пунктов, муниципальные перечни и планы с координатной основой, лицензируемый геокодер. Это направления поиска, не уже подтверждённые источники.

Проверить лицензию, право локального хранения и использования автодополнения, русские aliases, актуальность исторических названий, ограничения по территории. Для GeoNames требуется CC BY4.0 с пользовательской атрибуцией; для OSM применимы ODbL и происхождение производных данных. Не смешивать лицензии без оценки условий.


### Готовый результат

Минимальный набор данных с версией с ID, русским названием, различающей подписью, координатами, точностью, адресом источника датой и SHA, причиной допуска и лицензией. Для каждого кандидата — допущен, неоднозначен, отсутствует или отвергнут. Проверенный частичный набор допустим; не объявлять его полным каталогом России.

Не скачивать снова те же архивы стран и вариантов названий и глобальный alternateNamesV2. RuWiki 2110 имён без координат и эталонные тестовые данные нельзя использовать как рабочий геокодер. Полные архивы в CI были временными; перед использованием проверить наличие и SHA, в репозитории постоянно сохранены описания состава и выбранные исходные записи.

### Что сделать в доступном браузере

## B04 Новая пара М-4 и официальный километраж


### Точная установленная идентичность

Шесть сохранённых маршрутов новых территорий→Казань связаны с одной физической парой. Въезд: OSM node 4443232947, направленный переход way447135768→1182567076. Съезд: OSM node 358467208, way1211606940→28835034, М-4→Р 260. Переходы доказаны по полному trace выбранного маршрута. Инструкция манёвра начинается раньше и не заменяет фактический узел.

Для этой пары нет подтверждённой операторской области взимания и цены. В M4_GRAPH_ENDPOINT_REGISTER.json активных строк 0, pending-пара 1. Pending не участвует в начислении. Поиски физического перехода выполнены; задача сейчас — доказательства тарифа и километража, а не новый аудит шести маршрутов.


### Что передать тарифному исследователю

Попросить у оператора схему конкретных въезда/съезда и документ, связывающий их с тарифными endpoints, направлением и платным охватом. Нужна категория I, легковой автомобиль, без транспондера, продукт оплаты наличными или картой и дата действия. Датированный чек пригоден только вместе с точными границами и условиями проезда. Не присваивать сумму по ближайшему ПВП или одному имени М-4.


### Что передать GIS специалисту

Найти проверенный официальный километр каждого точного перехода: узел и направленные линии OSM→ветка дороги→шкала км→значение и погрешность. Уже найденная публикация 1038 км относилась к другой развязке; её нельзя присвоить этому узлу.

Модуль километража готов: 14 групп и 81 узел прежнего перечня, но дополнительных проверенных опорных точек и калиброванных участков нет. Для калиброванного участка нужны координатная полилиния, обе официальные отметки км, направление, scaleId/branchId, допустимое отклонение и проверяемый источник. Не проводить прямую между произвольными ПВП и не считать длину полилинии официальным километром.


### Критерий готовности

Каждая цена имеет точный направленный ключ, профиль, сумму, источник, срок действия и проверенную область взимания. Километры добавляются независимо от цены. ### Региональные дороги и действующие тарифы

Каталог платных сетей не является доказательством полного покрытия России. Для любого фактически выбранного платного участка нужны фактический проезд, операторский охват, действующая категория/способ оплаты/календарь и прямая цена. Исполнителю нужно проверить реестр и матрицу текущего коммита: какие строки активны, изолированы от начисления, справочные или недатированы, где отсутствует географическая идентичность. Старые 57 или 10 строк без дат относятся к прошлым этапам и не должны использоваться как текущий счётчик. Выдать актуальную выборку полей и причины исключения без повторного массового аудита.

М-1/М-3 и Одинцово имеют поздние корректировки операторского порядка, календаря и привязок. Одинцово 650 ₽ как базовый тариф в любое время уже реализовано по решению владельца. Не возвращать исправленную задачу в очередь по старой строке finding.


### Ейск и Майкоп против Москвы

Сохранены контрольные записи ответов V3 и 4 офлайн воспроизведения. Ейск дал 4340/5240 ₽, Майкоп 5040/6090 ₽ для четверга/субботы. Старые ожидания regression script обращались к V2, поэтому напрямую сравнивать их с V3 неправильно.

При отсутствии результата выполнить только недостающую часть на тех же контрольных входах и датах; полный runner не запускать. Различие версий не исправлять изменением тарифных чисел под ожидание теста.


### Агрегатные симптомы и выход

unknown-paid-road, expected-road-not-proven, engine_not_yet_composed объединяют разные причины и пересекающиеся кейсы. Название ожидаемой дороги не доказывает её проезд самым быстрым маршрутом. Для каждой новой находки выделять один физический участок, один отсутствующий факт и влияние на итог.

## B11 Производительность полного расчёта


### Что известно

Целевой ориентир — стараться укладывать полный расчёт примерно в 10 секунд. Общее SLA не установлено. Включаемый модуль calculationTiming добавляет Server-Timing и структурированные стадии обычной и специальной ветки без смены маршрута, цены или количества запросов.

Два одиночных замера серверных POST с реальной внешней сетью на CI host: Анапа→Краснодар 2.225 с,165.009 км,620 ₽; Донецк→Москва 7.318 с,1123.25 км,3050 ₽,special/dual/mainland и самый быстрый OSRM. Вторая сумма взята из существующей матрицы, отдельно с оператором не пересверена. Это не браузерный или Vercel end-to-end замер и не подтверждение всех направлений.


### Задание performance инженеру

Начать с конкретного нового медленного пользовательского запроса, его времени, версии и полного ответа. Разделить задержку ввода в браузере/поиск адреса, сеть пользователя, холодный запуск, маршрутные сервисы, сопоставление с дорожным графом, обязательную тарифную проверку, сериализацию и передачу. Сопоставить запрос и Server-Timing с серверными стадиями.

У параллельных интервалов есть перекрытия: их нельзя складывать как последовательные интервалы. Фиксировать полную длительность отдельно от времени провайдеров. измерение процессорного времени километража не является измерением полного пользовательского расчёта.

При доказанном узком месте предложить ограниченную правку: устранить дублирующую работу, переиспользовать уже полученный trace или безопасно ограничить fanout. Сначала подтвердить неизменность выбранного маршрута, обязательных проверок и цены. Не сокращать проверки платных участков и не отдавать промежуточную сумму как полный итог ради скорости.


### Критерий готовности

Воспроизводимый новый медленный случай, сопоставимые до/после условия и объяснённые границы вывода. Небольшой набор по конкретному отличию, а не расширение однотипного корпуса. Сохранены исходные запросы и ответы, стадии, ошибки и условия холодного или прогретого запуска.

Если задержка целиком у внешнего источника, явно указать это и поведение таймаута. Одного быстрого ответа недостаточно, чтобы объявить все направления укладывающимися в 10 секунд.

### Начало работы

Получить доступ к GitHub репозиторию 4regodatbe-cpu/mezhgorod-calculator. Работать в fix/v3-missing-route-prices-2026-10-15, PR14 оставить draft. Сначала прочитать AGENTS.md, docs/WORK_STATE.md, WORKFLOW_RULES.md, CHECKPOINT_PROTOCOL.md и OPTIONAL_MODULES.md. Зафиксировать текущий удалённый commit SHA/tree/PR и активные CI. Не писать в ветку при active/queued CI, не отменять проверки и не создавать второго writer. Не менять main, Android, резервную ветку и Production. Доступ к публикации — только по новому прямому поручению владельца.


### Неподвижные продуктовые правила

Только самый быстрый допустимый маршрут, легковой автомобиль без транспондера. Не добавлять альтернативу ради цены или искусственные заезды/съезды с повторным въездом. Для специальных территорий сохранить существующую географическую политику и проверенные полигоны; границы территорий не заменять countryCode.

Тарификация определяется датой отправления всей поездки, даже если проезд продолжается на следующий день. Для типовых дорог будниПн–Чт/повышенныеПт–Вс; у М-11 отдельный понедельник. Брать конкретный календарь продукта из текущего источника. Не вычислять отсутствующий тариф вычитанием или соседней ценой.

Неизвестное не 0 и не бесплатно; частичный итог не полный. Не сокращать обязательные toll checks ради 10 секунд. Benchmark coordinates и synthetic fixtures не переносить в live. Собственная дорожная сеть России остаётся отложенным проектом.


### Как сдавать каждый пакет

До долгого действия сохранить STARTED: входы, предел времени/запросов, ожидаемый результат и восстановление. Выполнить один ограниченный блок, проверить, записать DONE/FAILED/BLOCKED, обновить журнал и актуальное состояние, commit в разрешённую ветку, проверку точного результата в удалённой ветке. Затем продолжить независимый блок.

В отчёте: пользовательский эффект; причина; точную область изменения; что изменено; источник цены/границы/координат; raw и SHA; фактические проверки; ограничения; незакрытые вопросы; один следующий шаг. Статусы: исправлено и проверено, не воспроизвелось, заблокировано данными, отложено. Отдельно указать NOT_RUN и SKIPPED.

Для нового кода: целевые тесты, предусмотренный полный audit/quote API, ESLint, TypeScript/webpack. Исполнитель использует package.json и существующие runners; не запускает широкий аудит с реальными запросами ради небольшого исправления. Для изменений только документации проверить содержание, ссылки и сохранение без повторной маршрутизации.
